2. データモデル(insight.db)

scan_runs/asset_records/check_resultsがPhase 1の正準スキーマ、defect_recordsがPhase 2の評価結果。全テーブルがscan_run_idを直接持つため、トレンド集計はJOINなしにGROUP BY scan_run_idだけで書ける。

  • asset_records 1 –< check_results(1assetに複数check)
  • defect_records.first_seen_run_id / last_seen_run_id は scan_runs を参照(同一 asset_id + rule_id は1行のみ、upsertで更新)

3. シーケンス: CI定期実行

.github/workflows/insight-scan.yml が schedule(cron)と workflow_dispatch(手動)の両方で起動する。

  1. GitHub Actions → python -m ingest.run_scan --producer fs_scan
  2. insight.db に scan_run + asset_records を追記
  3. GitHub Actions → python -m rules.run_checks
  4. defect_records を upsert
  5. GitHub Actions → python -m output.cli_adapter --fail-on warn
  6. exit code (0=defectなし / 1=warn以上 / 2=fail検出 or 実行時エラー)
  7. exit code ≠ 0 の場合: insight-scan-failed ラベルのopen Issueを検索 → 無ければ新規作成(重複防止)
  8. 成功した場合: open状態の insight-scan-failed Issueをすべてクローズ

4. シーケンス: GUIからのスキャン操作

GUIはCLIと同じ関数を直接呼ぶだけで、判定ロジックの複製は一切ない。

  1. ユーザー → POST /scan(producer, target, since, run_checks)
  2. Flask → ingest.run_scan() で scan_run + asset_records を追記
  3. run_checksチェック時: build_context() + run_all_rules() → defect_records を upsert
  4. Flask → /runs/<scan_run_id> へ302リダイレクト
  5. ユーザー → GET /runs/<id>
  6. Flask → build_manifest(conn, scan_run_id) → bar_chart / table セクションを取得
  7. Flask → レポート画面(HTML)をユーザーへ返す

6. report_manifest.json スキーマ

ReportManifestBuilder が唯一の書き込み口。CLI/Excel/静的HTML/GUIはすべてこの形を読むだけ。

{
  "manifest_version": "1.0",
  "scan_run_id": 42,
  "generated_at": "2026-08-11T09:00:00Z",
  "sections": [
    {
      "section_id": "texture_resolution_histogram",
      "type": "bar_chart",
      "title": "テクスチャ解像度分布",
      "data": { "labels": ["256","512","1024","2048","4096","4096+"], "values": [12,48,120,30,4,0] }
    },
    {
      "section_id": "defect_summary",
      "type": "table",
      "title": "不具合一覧(severity>=warn)",
      "data": {
        "columns": ["asset_id","rule_id","severity","first_seen_run_id"],
        "rows": [["Assets/Textures/rock_d.png","naming_convention","warn",39]]
      }
    }
  ]
}

現在 build_manifest() が生成するセクションは6つ: texture_resolution_histogram / lod_fade_coverage / size_distribution / extension_breakdown / last_modified_distribution(いずれも bar_chart)、defect_summary(table)。

7. 拡張ガイド

新しい取り込みプロデューサーを追加する

  1. ingest/adapters/<name>_adapter.py を作成し、producer_id と scan(target_path, since) を持つクラスを @register で登録
  2. ingest/run_scan.py の import 行にファイルを追記(登録の副作用のため)
  3. その他は変更不要

新しい検知ルールを追加する

  1. rules/definitions/<rule_id>.yaml を作成
  2. 既存モジュールを再利用するか、evaluate(context, rule_def) -> list[DefectRecord] を実装
  3. rules/engine.py / rules/run_checks.py は変更不要

新しい集計軸を追加する

  1. trend/aggregations.py に純SQL関数を1つ追加
  2. output/report_manifest.py の build_manifest() に add_section() を1行追加
  3. CLI/Excel/静的HTML/GUIは自動的に反映

GUIに新しい画面を追加する

  1. webapp/app.py に @app.route(...) を追加
  2. webapp/templates/ にテンプレートを追加(base.htmlを継承)
  3. webapp/static/style.css のトークンを再利用
